**摘要**　数字孪生已成为无线网络设计与演进的常用工具。为现实系统建立准确的数字副本，可用于研究和分析系统表现与存在的问题，也能在无风险的环境中设计并测试新方案，验证后再将其应用于真实系统。6G 在设计与部署中有望高度依赖数字孪生，并有望为扩展现实（XR）与沉浸式通信提供稳健且普遍可用的网络。

本文提出 BostonTwin，把马萨诸塞州波士顿市的高保真三维模型与现有蜂窝基站部署地理空间数据合并，整理成可直接用于射线追踪的数据集。因此，BostonTwin 支持建筑模型的即时渲染和编程访问，并能准确表示真实波士顿市的电磁传播环境。此类传播表征的细节水平和准确性对于设计 6G 网络至关重要，有助于满足扩展现实、沉浸式通信等敏感且高带宽应用的严格要求。

## 1 引言

网络与数字系统日益复杂，需要新的综合设计和优化方法。数字孪生（DT）概念以有力的工具和抽象形式出现，可支持包括网络和多媒体方案在内的多种应用 [5]、[18]、[24]、[26]。孪生以极高的逼真度在数字空间中重建现实场景，使数字孪生可作为安全的测试环境，评估现实系统的不同配置。它既不影响现网性能及面向最终用户的服务质量，也可能在快于实时的环境中提前推演并评估真实系统的多个版本。此外，高保真数字副本能采集用于训练人工智能（AI）模型的数据，并能以现实中难以实现的灵活性及自动化能力开展此类数据采集。

以往网络研究采用数字孪生 [14]、[19]、[28]、[32]、[40]、[42]、[43]，以改善无线网络优化和配置、规划监测方案，并提高车载网络和卫星系统性能。多媒体系统也采用数字孪生 [4]、[22]、[35]、[41]，用于刻画移动用户的视频流服务质量、管理组播流的资源和优化 XR 系统的体验质量。然而，实现数字孪生颇具挑战。无线系统尤其如此，因为数字世界需要准确复现现实传播、协议栈、应用与用户行为模式。我们在 [39] 中迈出定义高保真无线数字孪生的第一步，提出 Colosseum 无线网络仿真器，将其作为空口无线网络的数字孪生，并介绍孪生无线信道与网络的工具链。

本文进一步构建能够真实复现无线场景的数字孪生。我们介绍 BostonTwin，这是一个面向城市尺度数字孪生的全自动工具链及数据集。它以波士顿市为对象，使用波士顿规划与发展管理机构（BPDA）公开的数据。我们实现并开源一组应用程序编程接口（API），将此三维模型接入 NVIDIA Sionna [20]、[21] 等常用射线追踪器，并将城市网格与真实地理位置上的基站等物体相融合，服务于蜂窝网络设计。BostonTwin 三维模型能在城市尺度上保留会显著改变无线信号传播的细节，这些细节也影响数字孪生的准确性。代码和数据分别见 [37]、[36]。

BostonTwin 的贡献如下。

- 将 BPDA 三维建筑模型 [9] 转换成以米为单位的多边形文件（PLY）模型。Mitsuba 等射线追踪器广泛采用 PLY，借此可以编程和快速渲染三维场景，并进行图形或射频（RF）射线追踪 [25]。转换代码和处理后的数据集见 [37]。
- 提供可交互和操作 BostonTwin 的 API，支持部署节点及兴趣点并进行地理定位，根据用户需求动态调整数字孪生的细节层级和精度，以及从完整城市场景中提取子场景。
- 通过 BostonTwin API，将射频射线追踪所需的兴趣点位置加入城市尺度三维模型。其中包括波士顿市的无线蜂窝基站位置，这同样是开放数据 [8]。该方法可扩展到移动接收机、其他无线系统或干扰源等要素。
- PLY 数据集与 BostonTwin API 可直接将三维网格输入 NVIDIA Sionna 电磁射线追踪器。本文利用它刻画波士顿市各分块的传播，以及网络对 XR 等第六代（6G）无线多媒体用例的支持能力。

**图 2：** 数据集组织。`bostontwin` 的两个主目录为 `boston3d` 和 `boston_antennas`。前者含 `meshes` 子目录和 `BOS_<L>_<N>.xml`、`BOS_<L>_<N>.geojson`、`BOS_<L>_<N>_tileinfo.geojson`，后者含 `antennas.geojson`。原图见 PDF 第 2 页。

BostonTwin 的方法和 API 简化了与数字孪生模型的交互，并提供准确的城市尺度三维数据集。与现有数字孪生 [6]、[16]、[33] 相比，BostonTwin 支持更大的规模，公开源代码，并集成其他先进的开源工具，由此支持开放科学研究。

本文结构如下。第 2 节介绍 BostonTwin 的数据和可操作三维模型及地理定位兴趣点的 Python 类。第 3 节描述操作 BostonTwin 和射频射线追踪器的工作流。第 4 节讨论 BostonTwin 的用例，即评估城市环境中沉浸式通信的覆盖与数据速率。第 5 节总结全文并讨论未来扩展。

## 2 BostonTwin 框架

BostonTwin 框架由 API 和两个主要数据源组成，即三维建筑模型与基站地理信息。分别可用 `BostonModel` 和 `BostonAntennas` 两个 Python 类访问对应数据。它们提供用于管理、操作及处理数据集的多个实用函数。

### 2.1 BostonModel 类

`BostonModel` 类包含波士顿市建筑三维模型的信息及其访问方法。数据来自 BPDA 公开的城市级三维智能模型 [9]，源于 2011 年的波士顿平面测绘，并定期使用 BPDA 城市设计模型、CyberCity 3D 和 LiDAR 数据更新。目前，BPDA 地理信息系统（GIS）实验室按 citySchema 模型 [12] 组织与管理数据。这种开放管理格式符合 ISO《开放档案信息系统参考模型》的要求 [30]，易于维护、更新和扩展。随着更多城市采用 citySchema，且三维模型不断细化，本文提供的 API 和数字孪生框架可以扩展到其他兼容城市和场景。

三维数据覆盖整个波士顿市，按 $N$ 个边长 1524 m（5000 ft）的正方形分块组织。命名格式为 `BOS_<L>_<N>`，其中 $L\in\{\mathrm A,\mathrm B,\ldots,\mathrm O\}$，$N\in\{1,2,\ldots,13\}$。原文把当前可用分块列于表 1。每个分块提供多种三维数据格式，如 Wavefront OBJ 和 SketchUp 文件，以及采用逗号分隔值（CSV）的模型目录。模型目录中的建筑坐标按（经度、纬度）表示，使用世界大地测量系统 1984（WGS84），即 EPSG:4326。OBJ 模型采用 BPDA 文档所述的自定义坐标参考系统（CRS）。具体而言，地理投影采用以英尺计的马萨诸塞州平面坐标系统，水平、垂直基准分别为 1983 年北美大地基准（NAD 83）和 1988 年北美垂直基准（原文缩写 NADV 88）。自定义 CRS 的原点为该平面中的 $(731100,2902900)$ ft，WGS84 坐标为西经 $71.223391^\circ$、北纬 $42.213379^\circ$。

citySchema 有多项优点，但该数据格式不适合物理仿真或编程访问。首先，需将全部数据改用国际标准化组织（ISO）所采用的单位，即米。其次，自定义 CRS 难以接入其他来源的数据，如带地理位置的数据。这限制了在场景中加入新要素的能力，而无线通信网络设计等用例需要这种能力。最后，虽然 BPDA 网站与数据集提供了许多可视化、目录查询和向商业应用导入模型的资源，仍缺少通过 Python 等编程语言访问数据的便利方式。因此，我们保留分块组织，将模型转换为另一种 CRS 和格式，并提供第 3 节所述的地理配准 API。

具体而言，将 OBJ 模型的单位转为米，使每个网格以 $[0,0]$ 为中心，全部顶点的坐标相对于模型自身中心。这简化了对单个网格的可视化和处理。

<span id="page-4"></span>

同时，定义 CRS 的工作交给用户，用户因而更容易使用自定义坐标系。为了逆转平移并对网格作地理定位，我们将各模型的地理参考信息放入相应分块的模型目录 `BOS_<L>_<N>.geojson`，分块本身的信息则存入 `BOS_<L>_<N>_tileinfo.geojson`。

**图 3：** 波士顿中心城区建筑模型的细节层级分布。图按 F–I 列、3–6 行标出分块，图例为 LOD 0、1、1.5、2、3、3.25、3.5、4、4.5。原图见 PDF 第 4 页。

我们还把 OBJ 模型转换成二进制 PLY 文件。PLY 是常用且标准化的数据格式，受 Blender [11]、Open3D [44]、Mitsuba [25] 等多数开源三维处理和渲染工具库支持，并受到推荐 [25]。生成的目录与文件树见图 2，公开数据见 [36]。

### 2.2 BostonAntennas 类

波士顿 GIS 部门还发布了该市批准安装小型蜂窝天线或分布式天线系统（DAS）的申请地理定位数据。2017 年 1 月 1 日之前和之后批准的申请分别在 “DAS/Small Cell Approved Locations” [7] 和 “Wireless Antenna Installation Requests Approved” [8] 两个数据集中发布。两者均采用 WGS84。我们统一列名与信息并将其合并，得到图 2 中的 `antennas.geojson`。

天线数据为二维数据，与 `BostonModel` 类不同，未提供天线高度。不过在多数情况下，天线的安装支架类型（`New_Pole_Type`）可据以确定一组可能高度 [34]。

### 2.3 BostonTwin 类

数字孪生通过 `BostonTwin` 类实现。该类包含一对 `BostonModel` 和 `BostonAntennas` 对象，用于访问城市尺度模型的信息。一个 `BostonTwin` 实例表示一个具体场景，并包含若干用于访问场景的实用函数。

场景由地理边界定义，见图 2 中的 `<scene_name>_tileinfo.geojson`，含对应区域内的所有数字孪生要素，即环境三维模型及基站位置。可通过相应的模型目录或 Mitsuba 场景文件访问，图 2 的对应文件为 `<scene_name>.geojson` 与 `<scene_name>.xml`。Mitsuba 文件包含场景三维渲染的若干基础设置、对场景中全部模型的引用，以及将各网格放到场景局部 CRS 的位置信息。局部坐标系统以米为单位，原点在场景中心。由 PLY 网格组成的 Mitsuba 场景可直接导入 Sionna，使用其交互 API 可视化和渲染，详见第 3 节。如第 2.1 节所述，我们保留分块组织，为每个分块定义场景并沿用 `BOS_<L>_<N>` 的命名。用户可把相应文件添加到数据目录，或通过图 4 所示专用 API 定义自定义场景。

与电磁（EM）信号相互作用的表面材料对其传播有显著影响。Sionna 提供一组国际电信联盟（ITU）材料，附有三维网格所需的电磁属性 [23]，每个网格与一种材料关联。在 BostonTwin 的预定义场景中，按模型目录中记录的模型类型分配材料。标为 Wall 的墙面使用 ITU 砖材，标为 Building 的建筑使用 ITU 混凝土，地面使用 ITU 中等干燥地面材料。借助模型目录的地理配准和描述信息，用户可在 Sionna API 或 Mitsuba 场景文件中定义、修改或定制材料。未来随着 BPDA 数据细节层级提高，计划支持由多种材料部件组成的网格。

## 3 BostonTwin 工作流

本节描述图 4 所示工作流及与 BostonTwin 框架交互的 API。

**加载场景**　用户可按第 2.1 节的规则指定分块名称，加载一个预定义场景，即图 4 上方红色箭头所示流程。场景会载入 Sionna，基站数据库则经过筛选，只保留分块内的基站。用户也可指定地理位置和半径，即图 4 左侧红色箭头所示流程。地理位置既可用（经度、纬度）元组表示，默认 CRS 为 WGS84/EPSG:4326，也可用采用不同 CRS 的 GeoPandas GeoDataFrame [15] 表示。系统将指定点半径范围内的要素加入新场景。

借助 API 的地理配准能力，BostonTwin 可方便地接入各种来源的数据，例如城市交通仿真器 Simulation of Urban MObility（SUMO）[31]，它可提供能输入数字孪生的逼真交通流模式。

此外，由于兼容 citySchema 格式，也容易集成其他数据集的三维数据。

**图 4：** BostonTwin 的工作流。地理坐标或预定义场景作为输入，API 设置场景并转换局部坐标。BostonTwin 与 NVIDIA Sionna 支持渲染及大规模电磁表征。原图见 PDF 第 5 页。

**部署无线设备**　如第 2.2 节所述，数字孪生包含波士顿市已经批准的基站位置，用于在真实位置部署无线设备。加载场景后可取得相应区域内的基站列表。用户可选择在 Sionna 中部署的基站，并指定其角色为 Sionna 发射机或接收机。用户还可将设备添加到自定义位置，使用地理坐标或局部坐标指定位置。这让部署用户设备等节点更加便捷。

**通过射线追踪表征射频传播**　如图 4 所示，BostonTwin 使用 Sionna 射线追踪器仿真数字孪生内的电磁波传播。该追踪器基于 Mitsuba 3，能在 GPU 上并行计算，大幅改善速度与可扩展性，细节见 [20]。此外，可通过 Mitsuba 渲染数字孪生，并用 Sionna API 与其交互。基于这些特点，本文选用 Sionna 作为开源射线追踪工具。第 4 节展示了射线追踪器（RT）能生成大规模场景的详细覆盖图，即使场景含数十万个三角形（表 1），运行时间也在秒量级。还可计算每对设备之间的点对点信道，设定任意的反射次数，并选择是否包含衍射和散射路径。

**简化三维模型**　BostonTwin 还提供实用函数，提高数字孪生的可用性与交互便利性。大规模电磁仿真的内存需求很高，这也与模型的三角形数量有关 [29]。因此，可简化 BostonTwin 的建筑三维网格，以减少三角形数量，降低硬件需求和运行时间。我们采用 Open3D 库，它提供多种网格简化方法。简化后的三维数据可通过与原始数据相同的流程导入、加载和使用。然而，减少顶点应谨慎，因为精度降低可能导致几何不一致，并降低电磁表征的准确性。

## 4 面向沉浸式通信的数字孪生

我们考虑一个简化的 6G 沉浸式通信场景，展示 BostonTwin 作为数字孪生的能力。具体使用 12.7 GHz 载频，这是所关注的 6G 新频段 FR-3 的候选频率之一 [13]、[27]。在讨论新频谱分配的初始评估阶段，可靠仿真工具尤其重要。例如，可评估对现有利益相关方的影响 [38]，并刻画传播情况以及不同环境的部署设计。为此，既需要准确的传播模型，也需要细致表示传播环境。

与传统 FR-1 相比，FR-3 提供更宽的带宽，传播特性也优于毫米波。

<span id="page-6"></span>

**图 5：** 波士顿中心城区的覆盖图。（a）信噪比（SNR）。（b）达到 XR 吞吐量要求的位置。（c）达到 V2X 扩展传感器吞吐量要求的位置。后两图中绿色代表满足要求的区域。各图以 F–I 列和 3–6 行标注地理分块，图（a）的 SNR 色条由 $-10$ 到 $20$ dB。原图见 PDF 第 6 页。

我们分析增加的带宽能否满足两类沉浸式通信应用，即 XR 和 V2X 中的视频流传输。按照第 3 节的工作流，选择 16 个场景（分块 $\mathrm{BOS\_L\_N}$，其中 $L\in\{\mathrm F\text{–}\mathrm I\}$、$N\in\{3\text{–}6\}$），代表原文所述波士顿中心城区面积 83.6 km² 的区域。完整网络及射线追踪器配置见表 3。

首先用 Sionna 射线追踪器仿真电磁波传播，纳入各分块内的所有基站，在带宽 $B=400$ MHz 下刻画各分块的 SNR。从图 5(a) 可见，因基站密度较高，市中心（G_4–5、H_3–4、I_3–4）的服务覆盖较好，SNR 峰值超过 24 dB。最南侧的分块基站密度较低，覆盖也较差。在查尔斯河两岸（如 F_4、G_4）或波士顿公园（H_4 分块中部）等开阔区域，可看到信号在没有建筑物阻挡的自由空间传播时的 SNR。

接着，用 Shannon 容量公式 $C=B\log_2(1+\operatorname{SNR})$ 计算可达容量 $C$。两种沉浸式通信场景的吞吐量要求分别为 XR 的 30 Mbps [3]、[10]、[17]，以及 3GPP 技术规范 [2] 中 V2X 用例“支持 V2X 应用的用户设备之间的视频共享”的 700 Mbps。评估中筛去容量不满足要求的位置。图 5(b) 显示，现有基站在城区大片范围内能提供足以支持 XR 的吞吐量。即使采用 FR-3 频段，V2X 用例的容量要求也只在基站附近得到满足。这需要更密集的部署、更高的发射功率或更大的带宽。

因此，BostonTwin 可用于分析既有场景、规划并测试进一步的网络部署、研究系统规模设置，以及为新的编排方案提供大规模、安全且逼真的测试环境。

## 5 结论

本文提出城市尺度的数字孪生框架，简化面向下一代无线网络及多媒体应用的射线追踪研究。我们使用波士顿市的开放数据，构建可方便解析、操作和导入常用射频射线追踪框架的数据集。论文先描述数据集及其交互代码，再介绍把三维模型与自定义的地理定位兴趣点结合，并将信息传入 NVIDIA Sionna 射线追踪器的工作流。最后通过用例展示 BostonTwin 的灵活性与规模。在波士顿的准确数字表示上运行射频射线追踪，评估无线网络能否在 6G 关注的新频段支持不同类型的下一代多媒体应用。

数据公开于 [36]，代码按 MIT 许可开源，见 [37]。未来会利用 BostonTwin 在 Colosseum 中创建基于 RT 的逼真波士顿场景，开展蜂窝和无线系统的全栈孪生研究，并通过与实测对比进行验证。我们还将纳入更先进的地形模型，包括地面高程，并集成 SUMO 等移动性仿真器。
