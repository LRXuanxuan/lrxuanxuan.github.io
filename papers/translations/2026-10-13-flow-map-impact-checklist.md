# Flow Map Denoisers 附录 E 与 NeurIPS 论文检查清单

对应原文第 53—60 页。按原文逐项保留“问题、回答、理由、指南”的结构。检查清单为 NeurIPS 要求的投稿自查材料，原文作者的回答不表示译者进行过独立验证。

## E. 更广泛的社会影响

在测量约束下生成内容的图像恢复方法，可能产生**看似合理但并不真实的细节**。当工作点靠近失真—感知权衡中的感知端，或者退化算子存在较大零空间（例如图像修复）时，这类问题尤其突出。

在医学成像、司法鉴证或安全等敏感应用中，这种幻觉（Hallucination）可能导致错误决策。本文研究的前瞻参数使权衡更加明确且可控，允许使用者在忠实程度至关重要时选择低失真的工作点。但是，在用于高风险场景之前，仍应对恢复结果进行验证。

## NeurIPS 论文检查清单

### 1. 研究主张（Claims）

**问题：** 摘要和引言中的主要主张，是否准确反映论文的贡献与适用范围？

**回答：** 是（Yes）。

**理由：** 摘要与引言明确区分了三个主张区域：各向同性高斯目标的去噪问题中严格 DP 最优（定理 1）；自然图像去噪中的经验 DP 遍历（第 3.3 节）；没有最优性保证的一般逆问题经验 DP 遍历（第 4、6 节）。通过广泛消融和基线比较支持这些主张。

**指南：**
- 若回答“不适用”（N/A），表示摘要和引言没有包含文中的主张。
- 摘要和／或引言应明确说明论文主张、贡献、重要假设及局限。回答“否”或“不适用”通常不利于审稿评价。
- 主张必须与理论和实验结果相匹配，准确说明结论预计在多大范围内可以推广。
- 可以把尚未实现的愿景作为研究动机，但必须明确它们尚未由论文实现。

### 2. 局限性（Limitations）

**问题：** 论文是否讨论本工作的局限？

**回答：** 是。

**理由：** 第 7 节和附录 C.13 讨论局限，包括高斯结果的适用范围（第 3.2.1 节、附录 D.2.3）、缺乏收敛保证（附录 D.4）、DP 遍历可能不单调，以及训练成本（附录 B.1）。

**指南：**
- “不适用”表示工作没有局限，“否”表示存在局限但论文没有讨论。
- 鼓励单列“局限性”章节。
- 应指出强假设，以及结果对假设违背的鲁棒性，包括独立性、无噪、模型指定正确、渐近近似仅局部成立等；还须解释这些假设在实践中如何失效及后果。
- 应反思研究主张的范围，例如只在少量数据集或少数次运行中验证。经验结果通常还依赖应当明确说明的隐含假设。
- 应讨论影响性能的因素。比如人脸识别在低照度或低分辨率下失效，语音转文字在术语密集场景中难以生成准确字幕。
- 应讨论算法的计算效率与随数据量增加的扩展能力。
- 如适用，应考虑隐私和公平性方面的局限。
- 作者可能担心坦诚局限会成为拒稿理由，但让审稿人发现被隐瞒的缺陷后果更严重。应根据专业判断推动透明的学术规范；审稿指南要求不得因为坦诚讨论局限而惩罚作者。

### 3. 理论假设与证明（Theory Assumptions and Proofs）

**问题：** 每项理论结果是否给出完整假设和完整、正确的证明？

**回答：** 是。

**理由：** 定理 1 明确陈述了假设；完整证明、辅助引理和多维讨论均见附录 D。

**指南：**
- 若没有理论结果，回答“不适用”。
- 全部定理、公式和证明都应编号并进行交叉引用。
- 定理陈述应明确给出或引用所有假设。
- 证明可以放在正文或补充材料；若放在补充材料，建议正文给出简短证明思路，帮助形成直觉。
- 反过来，正文中的非正式证明应在附录或补充材料中提供严格版本。
- 正确引用证明依赖的定理与引理。

### 4. 实验结果可复现性（Experimental Result Reproducibility）

**问题：** 无论是否提供代码和数据，论文是否充分披露影响主要结论或主张的全部实验复现信息？

**回答：** 是。

**理由：** 算法 1 清楚描述算法，附录 B.2 明确报告全部超参数及数据集。投稿时还附带源代码（原文称如获接收，将公开于 GitHub）。

**指南：**
- 若论文没有实验，回答“不适用”。
- 对实验论文回答“否”会令审稿人关注，因为无论是否提供代码和数据，可复现性都很重要。
- 若贡献包含数据集和／或模型，应说明采取了哪些措施让结果可复现或可核查。
- 可复现性存在不同实现途径：新架构可以通过完整的结构说明复现；模型加实证评价可能需要同数据集复现训练，或者让研究者使用原模型。开源代码和数据通常有效，但还可用详尽复现指南、托管模型访问、发布检查点或其他与研究性质相适应的方式。
- NeurIPS 不强制开源代码，但要求为每篇投稿提供合理的复现途径，例如：（a）新算法应说明如何复现；（b）新架构应清晰、完整地描述；（c）新模型（如大语言模型）应提供可访问的模型或可复现训练的途径（如开源数据集或数据构建说明）；（d）若存在困难，可以说明特殊的复现方式。闭源模型的访问可能有限，例如仅限注册用户，但仍应让其他研究者有核验的途径。

### 5. 数据和代码开放获取（Open Access to Data and Code）

**问题：** 论文是否开放提供数据和代码，并在补充材料中附上足以忠实复现实验的指令？

**回答：** 是。

**理由：** 实验复现代码已公开于 https://github.com/nzilberstein/Flow-map-denoisers 。

**指南：**
- 不包含需要代码的实验时可回答“不适用”。
- 详见 NeurIPS 代码和数据提交指南：https://neurips.cc/public/guides/CodeSubmissionPolicy。
- 鼓励释放代码和数据，但承认并不总是可行，“否”是允许的。除非公开代码本身构成核心贡献（例如新开放基准），否则不能仅因未公开代码拒稿。
- 复现指令应包含精确命令和运行环境。
- 作者应说明原始数据、预处理数据、中间数据和生成数据等各类数据的获取与准备方式。
- 应提供重现新方法和基线全部实验结果的脚本；如只复现部分实验，应说明省略哪些及原因。
- 投稿时应按需要保留匿名性，例如使用匿名下载地址。
- 推荐尽量在附录或补充材料中详细披露，也允许提供数据与代码 URL。

### 6. 实验设置与细节（Experimental Setting/Details）

**问题：** 是否指定了理解结果所必需的训练和测试细节，包括数据划分、超参数、选择方式及优化器？

**回答：** 是。

**理由：** 见附录 B.2。

**指南：**
- 无实验时回答“不适用”。
- 正文应包含理解实验与结果所需的关键设置细节。
- 全部实现细节可以放在代码、附录或补充材料。

### 7. 实验统计显著性（Experiment Statistical Significance）

**问题：** 是否恰当报告并定义误差棒或其他反映统计显著性的信息？

**回答：** 是。

**理由：** 见附录 C.1。

**指南：**
- 无实验时回答“不适用”。
- 至少应为支持论文核心主张的实验提供误差棒、置信区间或显著性检验。
- 应说明误差棒包含的变异来源，例如训练／测试数据划分、随机初始化、参数抽样或固定实验条件下重复运行。
- 应说明误差棒的计算方法，例如闭式公式、库调用或 bootstrap，以及作出的分布假设（如正态性）。
- 必须说明误差棒表示的是标准差还是均值标准误。
- 可以报告一个标准差（1-sigma）误差棒，但须明确指出。若未验证误差正态性，最好报告两个标准差误差棒，而不要宣称它是 96% 置信区间。
- 对非对称分布，应避免对称误差棒跨越有效范围，例如给出负错误率。
- 若图表报告了误差棒，应在正文中解释其计算方法，并引用对应图表。

### 8. 实验计算资源（Experiments Compute Resources）

**问题：** 是否为每项实验提供复现所需的计算资源信息，包括计算设备类型、内存及运行时间？

**回答：** 是。

**理由：** 附录 B.1 报告了采样和训练所用的计算资源。

**指南：**
- 无实验时回答“不适用”。
- 应报告 CPU 或 GPU 的型号、内部集群或云服务，以及内存和存储等相关信息。
- 应报告各次独立实验的计算消耗并估计总计算量。
- 应披露整个项目是否耗费了比论文中所报告实验更多的算力，例如未纳入论文的初步试验或失败实验。

### 9. 伦理规范（Code of Ethics）

**问题：** 研究是否在各方面遵守 NeurIPS 伦理规范：https://neurips.cc/public/EthicsGuidelines ？

**回答：** 是。

**理由：** 作者阅读了 NeurIPS 伦理规范，并确认论文满足其各项要求。

**指南：**
- “不适用”表示作者没有审阅 NeurIPS 伦理规范。
- 若回答“否”，应解释为何需要偏离该规范的特殊情况。
- 应保持匿名性，例如由法律或所在司法辖区要求造成的特殊考虑，不应泄露身份。

### 10. 更广泛的影响（Broader Impacts）

**问题：** 论文是否同时讨论研究工作的潜在积极社会影响与消极社会影响？

**回答：** 是。

**理由：** 见附录 E。

**指南：**
- “不适用”表示研究不产生社会影响。
- 回答“不适用”或“否”时应解释原因。
- 消极影响的例子包括恶意或意外用途（如虚假信息、生成虚假档案、监控）、公平性风险（系统部署可能不公平对待某些群体）、隐私和安全风险。
- 会议认识到许多论文是基础研究，与特定应用甚至部署没有直接联系；但只要存在直接通往负面应用的途径，就应指出。例如，更优质生成模型可能被用于 Deepfake 虚假信息，有必要提示；但不必声称任何通用神经网络优化算法都直接支持 Deepfake。
- 应分别考虑预期用途且正常工作时可能造成的损害、预期用途但结果错误时的损害，以及蓄意或无意滥用的损害。
- 若存在负面影响，可讨论缓解策略，例如受控模型发布、与攻击方案配套的防御、滥用监测、长期反馈学习监控，以及提高机器学习效率与可访问性。

### 11. 安全保障措施（Safeguards）

**问题：** 对于可能被高风险滥用的数据或模型（如预训练语言模型、图像生成器、抓取数据集），论文是否说明了负责任发布的安全保障措施？

**回答：** 是。

**理由：** 作者使用经过整理的成熟数据集，并确认所训练模型满足安全保障要求。

**指南：**
- 若研究不涉及此类风险，可回答“不适用”。
- 发布具有高风险滥用或双重用途可能的模型时，应采取必要保障以控制用途，例如要求遵守访问与使用约束、设置安全过滤器。
- 由互联网抓取的数据集可能存在安全风险，应说明如何避免发布不安全图像。
- 会议承认有效保障不易实现，也并非每项研究都需要，但鼓励作者尽最大努力考虑这些问题。

### 12. 已有资源的许可（Licenses for Existing Assets）

**问题：** 对所用现有资源（代码、数据、模型）的创造者或所有者，是否正确致谢、明确说明和遵守许可及使用条款？

**回答：** 是。

**理由：** 所有使用的外部代码都通过引用原始论文予以认可。非作者本人提供的资源包括主干网络架构（引用 Karras et al., 2022；Song et al., 2021）和公开数据集（附录 B.1）。

**指南：**
- 未使用已有资源时回答“不适用”。
- 应引用生成代码包或数据集的原始论文。
- 应说明使用的资源版本，可能时给出 URL。
- 应列出各资源的许可名称，例如 CC-BY 4.0。
- 若从特定网站抓取数据，应提供该来源的版权及服务条款。
- 发布资源时，应在包内提供许可证、版权和使用条款。paperswithcode.com/datasets 为部分流行数据集收集了许可信息，其指南可以协助判断许可。
- 若将已有数据集重新打包，应同时提供原始许可及变更后的衍生资源许可。
- 若网上没有许可信息，鼓励联系资源创造者。

### 13. 新资源（New Assets）

**问题：** 论文引入的新资源是否具有充分文档，且文档与资源一起提供？

**回答：** 是。

**理由：** 模型和数据集的相关信息见附录 B.2。

**指南：**
- 不发布新资源时回答“不适用”。
- 研究者应在提交中使用结构化模板描述数据集、代码和模型，包含训练、许可、局限等信息。
- 应讨论使用他人资源时是否取得同意及同意方式。
- 投稿时按需要匿名资源，可使用匿名 URL 或匿名 ZIP。

### 14. 众包与人类受试者研究（Crowdsourcing and Research With Human Subjects）

**问题：** 涉及众包或人类受试者的研究，是否提供参与者收到的完整说明、适用时的截图，以及补偿细节？

**回答：** 不适用（N/A）。

**理由：** 本研究没有人类受试者实验。

**指南：**
- 无众包或人类受试者研究时回答“不适用”。
- 信息可放在补充材料，但若人类受试者是核心贡献，应尽可能在正文披露。
- 按 NeurIPS 伦理规范，数据收集、整理或其他劳务参与者至少应获得其所在国家／地区的最低工资。

### 15. 机构审查委员会批准（IRB Approvals or Equivalent）

**问题：** 是否描述研究参与者的潜在风险、是否向参与者披露风险，以及是否获得机构审查委员会（IRB）或本国本机构相应审查批准？

**回答：** 不适用。

**理由：** 本研究没有人类受试者实验。

**指南：**
- 无众包或人类受试者研究时回答“不适用”。
- 不同国家可能要求人类受试者研究获得 IRB 或相应批准；若已获得，应在论文说明。
- 各机构程序可能存在很大差异，但应遵守 NeurIPS 伦理规范和本机构指南。
- 初次匿名投稿时，不应透露可能破坏匿名性的审查信息（例如执行审批的机构）。

### 16. 大语言模型使用声明（Declaration of LLM Usage）

**问题：** 若大语言模型是本研究核心方法中重要、原创或非标准的组成部分，论文是否说明其用途？如果仅用于写作、编辑或排版，不影响核心方法、科学严谨性或原创性，则无需声明。

**回答：** 不适用。

**理由：** 本文的任何核心模块均不包含 LLM。

**指南：**
- 若核心方法开发不涉及把 LLM 作为重要、原创或非标准组成部分，可回答“不适用”。
- 关于何时需要声明，参阅 NeurIPS 手册中的大语言模型政策。
