# 轻绘水彩笔刷：来源与实现约定

更新：2026-11-22。三种笔触在轻绘现有 Canvas 2D、当前图层和整笔浓度流程中实现；网页版及以后重建的 Windows / Android 安装包共用源码。网页版更新不代表已安装的原生包立即更新。

## 三种笔触

| 笔触 | 目标手感 | 合成约定 |
| --- | --- | --- |
| 湿水彩 | 新笔接触同层旧色时拾色、混合，形成柔和接色与纸面斑驳。 | 持续湿纸模式；使用当前层像素取样和光谱近似混色。 |
| 干水彩 | 透明薄涂，抬笔后再落一笔会出现明显的重叠和加深。 | 每笔独立罩染，浓度整笔合成一次，不搅动底层颜色。 |
| 颗粒枯笔 | 较少含水的干擦感，颗粒、缺口和纸面起伏更突出。 | 每笔独立透明合成，用纹理控制落色覆盖。 |

这里的“干水彩”指干后罩染（wet-on-dry / glazing），不等于几乎无水的枯笔（drybrush）。第三支以不同的落色覆盖和纹理表现补充前两支，不以不同名称重复同一个渲染参数。

## 湿纸行为与图层边界

湿水彩采用**显式的持续湿纸模式**：落笔时从选中图层当前已有的像素拾色，接触范围内的颜色可再次混合。没有按时间变化的湿度场，也没有后台蒸发、颜料流动或等待晾干的计时器；换色或暂停作画不会让纸面自动干燥。

此模式不记录旧像素究竟来自哪一种颜料或画笔。只要在同一图层，之前的颜色都可能被湿笔重新化开，包括先前的干水彩或普通笔迹。需要保持清晰的线稿或已经固定的局部颜色时，应放在独立图层。湿笔不能从其他图层或纸张背景拾色，也不能修改它们。

取样必须以本次笔触开始时的当前图层为准，保留图层位移、缩放与现有 `samplesLayer` 约定。撤销、重做、擦除、打开工程或复制图层之后，下一笔读取实际像素，不保留能使旧颜色重新出现的隐藏湿色画布。

干水彩与枯笔沿用整笔透明度流程，避免逐个落点重复乘浓度。纸纹和斑驳用于调制颜料覆盖；透明区域保持真实 alpha，不烘焙白色纸底。笔划、图层与工程记录继续由现有应用管理。

## 淡彩与可调质感

用户要求以淡淡、透纸的上色为主。默认湿/干罩染使用连贯而轻微的纸纹，
枯笔才显著露白；水彩内部颜料覆盖与顶部整笔浓度相乘，不把半透明伪装成白底。
按后续“圆润一点”的要求，湿笔与罩染的外缘过渡略加宽，默认边缘扰动温和收敛；
圆形起收笔与连续笔身相接，边缘斑驳调到 100% 时仍保留充分的不规则度，枯笔保持原有干擦感。

| 控件 | 引擎/工程字段 | 范围与含义 |
| --- | --- | --- |
| 笔尖水分 | `watercolorWater` | 0–1；调笔边柔度、湿笔局部渗化与含色量。 |
| 边缘斑驳 | `watercolorEdge` | 0–1；0 关闭不规则外缘及外缘积色，越大越明显。 |
| 水纹强度 | `watercolorBloom` | 0–1；0 关闭浅色水痕与边界积色；是程序外观近似，不是动态回流水体。 |
| 浓淡变化 | `watercolorVariation` | 0–1；调宽范围内颜料浓淡，0 关闭；不向颜色添加随机 RGB 杂色。 |
| 颗粒 / 纹理粗细 | `textureScale` | 0–4；调整纸纹空间大小，不改变笔径；0 关闭纸纹颗粒。 |
| 颗粒 / 纹理密度 | `textureDensity` | 0–2；正值调整落墨覆盖与留白，默认 1；0 关闭纸纹颗粒。 |

前四项的界面以 0–100%、5% 步长表示。三个效果相互独立，原有浓度、防抖与压感继续工作；
颗粒粗细或密度任意一项为 0 即关闭纸纹颗粒，笔刷仍正常出墨；边缘斑驳、水纹和浓淡变化
继续使用各自设置。两项都恢复到正值后重新启用颗粒，0% 偏好及工程值应原样保留。
参数按笔分别保存在本机，当前笔写入 `.lrxdraw`。本机已调过的偏好优先；缺省或无效字段
回到相应笔的推荐值，合法但越界的值收敛到范围内。重置只影响当前笔。

默认水分/边缘/水纹/浓淡为：湿画 70/30/20/25%，干罩染 40/30/15/25%，枯笔 15/35/10/30%。
试笔图用两个真实笔划展示交叠，同样由临时工作层整笔合成，不另用装饰图片替代实际引擎。

浏览器使用普通 `<script>` 加载后提供全局 `spectral`；Node 的 CommonJS `require()` 返回相同 API，无需构建步骤。代码在本地运行，不通过第三方服务处理画作，绘制时不依赖外部 CDN。

```js
// 浏览器：在笔刷模块之前加载 vendor/spectral/spectral.js。
// Node：const spectral = require('../assets/drawing-studio/vendor/spectral/spectral.js');
const yellow = new spectral.Color('#FCF046');
const blue = new spectral.Color('#3375DA');
const mixed = spectral.mix([yellow, 0.5], [blue, 0.5]);
const rgb = mixed.sRGB; // [111, 186, 99]，通道范围 0–255。
```

此版本导出 `Color`、`mix`、`palette`、`gradient`。`mix` 接收若干 `[Color, factor]` 对；不能套用旧版或其他库的 `mix(rgb1, rgb2, t)` 接口。因子必须是有限的非负数，至少一项为正。

Spectral.js 用七种基础反射率重建 RGB 对应的 38 点光谱，再使用简化 Kubelka–Munk 模型近似颜料混合。其有效浓度还受亮度、着色强度和因子平方影响；调用系数不能直接宣称为严格的颜料质量比例。RGB 也无法唯一确定实物颜料，因此视爵等色卡在屏幕上的混色不构成对应实物颜料的准确配方。

## 计算与资源选择

采用当前图层局部取样、可复用笔尖/纸纹与有界混色缓存；避免在每个全分辨率像素上反复构造光谱颜色对象，也不建立 38 通道的全尺寸湿度/颜料历史。纹理、笔尖和查找结果可以适当缓存，以减少落笔时重复计算，但缓存必须有上限，不能随作画时间无限增长。

不运行持续的全画布流体求解，不在停笔后继续占用动画循环。水彩参数和纹理改变只作用于新笔触。依赖体积、运行时内存和实际落笔速度分别度量，不能用下载文件大小替代内存或性能验收。

这是一种水彩笔触与混色的可控近似：不模拟真实水流、蒸发、回流、毛细扩散、多种颗粒沉降速度或完整的光学罩染层。纸纹、软边和积色不应被宣传为严格物理仿真。

## 验收边界

- Vendor 已核验 CommonJS 与浏览器 UMD 导出、28 组跨运行方式混色一致性、通道有限值，以及黄色与蓝色形成绿色的示例。浏览器全局检查在 Node VM 中执行，不能称作真实浏览器或手写笔硬件测试。
- 笔刷集成另行检查湿笔跨次拾色、干笔跨次重叠、枯笔颗粒、当前层隔离、真实 alpha、撤销/重做、工程往返、零浓度和快速连续落笔。
- 用户设备的鼠标、数位板、手机压感与帧率需要对应环境实测。开发机像素测试和合成指针事件不代替这些实机验收。
