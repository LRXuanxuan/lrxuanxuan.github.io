# 轻绘 Android 版

Android 版复用 `/drawing-studio.html`、`/color-block-studio.html` 与现有本地绘画模块。
安装包内包含两间画室及按需读取的 PDF.js 资源；不另做一套画板，不把 Chromium
运行时、外部字体或参考图片加入安装包。网站继续独立使用。

## 使用方式

- 安装后进入轻绘画板。手机和平板默认收起左侧参考栏，点“参考”即可展开。
- 手指默认用于平移画布；想用手指画画，在“面板”顶部勾选“手指绘画”。
  触控笔压感仍取决于设备及系统 WebView 实际提供的 Pointer Events。
- “图片 / PDF”“打开”“导入图片”使用 Android 系统文件选择器。
- “存工程”保存 `.lrxdraw`，用于保留图层、参考和继续编辑；普通图片可导出
  PNG、JPEG、WebP，有限色块与线稿可导出真实路径 SVG。
- “归纳练习室 / 轻绘画室”切换保留同一对画室。“带参考去画画”更新参考，
  不替换当前画作。
- 网页、Windows 版和 Android 版各自保存本机续画，跨版本迁移请导出并导入
  `.lrxdraw`。卸载应用或清除应用数据前，先主动保存工程文件。

Android 系统版本和 WebView 版本是两项条件。即使系统达到最低版本，过旧的
Android System WebView 也可能缺少所需浏览器能力。应保留明确的更新提示，
不能把最低系统版本描述为全部设备、全部触控笔兼容保证。

## 源码与资源

| 位置 | 职责 |
| --- | --- |
| `android/app/src/main/java/` | 原生窗口、同源资源、文件选择与保存、退出及生命周期 |
| `android/android.js` | 复用 `DrawingDesktop.save / ready` 的 Android 适配层 |
| `android/app/src/main/AndroidManifest.xml` | 应用身份、最低权限与入口 |
| `tools/build_drawing_android.py` | 从现有网站生成离线资源，并检查资源闭包 |
| `.github/workflows/drawing-android.yml` | 固定工具版本的编译、验证与构建产物 |
| `tools/test_drawing_android.cjs` | 原生消息模拟下的导出与关闭契约回归 |

固定应用 ID 为 `io.github.lrxuanxuan.lightdraw`。固定本机资源源站为
`https://appassets.androidplatform.net`，并将离线文件根目录对应到该源站 `/`。
保留网页已有的根相对资源路径；不使用 `file://` 放宽文件访问，不把本机页面
改为在线网站的快捷入口。

构建生成的 assets、Gradle 缓存、APK、签名文件与密钥不能提交到源代码仓库。
`android/` 已从 Jekyll 站点输出排除。Windows 版的源码与已发布安装包独立维护。

## 原生接口边界

原生消息只接受可信本机源站的顶层页面。外部链接交给系统浏览器；外部页面、
子框架和导入文件不得获得本机保存或退出接口。不要增加通用“执行 JS”、
任意文件路径、任意网络请求或命令执行桥接。

文件选择与导出使用 Android 的 Storage Access Framework，由用户在系统界面
指定文档。避免申请整个存储空间、相册、摄像头或麦克风访问权限。

导出复用网页已有语义：`DrawingDesktop.save(blob, name)` 只有在实际写入完成
后才能返回 `true`；取消返回 `false`；失败抛出错误。必须按顺序分块并核对
总字节数、请求 ID、所属 WebView 和完成回执。不能把打开保存选择器当作成功，
也不能把失败后的任意 URI 删除当成“清理临时文件”。

PDF 主模块和 worker 的 `.mjs` 应以 JavaScript MIME 返回，`.wasm` 应以
`application/wasm` 返回。不要依赖不同 Android 版本中不一致的扩展名推断。
普通启动仍只加载画板资源，PDF 仅在用户导入时初始化。

## 保存、退出与多窗口

两间画室需要保留两个活 WebView 以及 `window.open` / `opener` 的配对语义。
不能用一个 WebView 来回加载 URL 来替代，否则绘画操作历史和教学调整会丢失。
旋转屏幕不应重建并清空正在编辑的页面；系统栏、屏幕缺口和软键盘需要正确让位。

退出应先完成当前笔画、等待导出并调用现有 `prepareToClose()`，确认最后一版
草稿已经落盘。失败时保留内存画面，允许继续编辑和另存工程。
应用退到后台时尽早请求保存；Android 强制结束进程、磁盘写满等情况不能保证
异步保存一定完成，主动导出的工程仍是可靠的迁移与备份方式。

## 签名与发布

正式 APK 使用固定专用签名密钥。升级必须沿用同一应用 ID 和签名证书，
并递增 `versionCode`；不要每次构建生成新密钥，不把临时 debug 包当正式版。

当前构建路线允许 CI 输出对齐的 unsigned release APK 与 Android 官方
`apksigner.jar`，在保有私密签名密钥的环境中完成签名与 `apksigner verify`。
公开构建产物不能包含 keystore、密钥密码、含密码的环境文件或私密签名备份。
没有安全配置签名 secrets 时，不自动发布未签名包，也不绕过权限建立公开密钥。

首次签名后应保存 APK、源码提交 SHA、文件 SHA-256、签名证书 SHA-256，以及
私密的长期签名备份。后续更新必须找回该备份；如果签名密钥不可用，不应悄悄
换签名并声称用户可以直接覆盖安装。

## 最低验收范围

1. 离线资源完整：两页、绘画模块、PDF worker / wasm / 字体映射及上游许可证。
2. release 编译、APK 应用 ID / 版本 / 最低系统信息、对齐、签名验证通过。
3. Android 模拟器或真机实际启动，本机 HTTPS 页加载成功，基础存储可用。
4. 两间画室切换后仍保留画作与教学状态，手机布局默认收起参考栏。
5. 系统文件选择可以取消；图片、PDF、工程的实际读取路径可工作。
6. 导出取消不会误记成功；分块写入完成后才报告成功，错误不会静默丢文件。
7. 返回、旋转、后台恢复、未完成导出和保存失败分别核对。
8. 分清源码审查、消息模拟测试、Android 模拟器与真实手机/触控笔实测，
   没有硬件证据时不得宣称真机压感、性能或防掌触已经验证。
