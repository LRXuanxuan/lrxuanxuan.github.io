# 日签库维护规范（Daily Sign Standard）

> 适用于 `/assets/data/quote-pool.json` 中的所有签文，以及未来新增的小说划线、散文、诗歌、电影台词、歌词、演讲摘录等。
> **这是长期入库约定。未来维护者与 AI 代理在增删改日签前均应先阅读本文件。**

## 一、总原则

1. **一句一签，一个主准则（aspect）。** 以**整句话的中心意义、语气、情绪和意象在语境中的实际作用**确定准则，而非数关键词、见词贴标签、给十四准则配额，或按照作者/书名直接推断。
2. **灯不再是兜底准则。** 当一句话同时符合灯和一个同样合理、更具体的非灯准则时，优先选非灯准则；但句子的重点确实是**理性与启迪、真理与洞见，以及真理的不仁、知识带来的残酷或求知者的疯狂**时，应明确归灯，不能为了降低灯的数量而错分。
3. 不追求十四准则平均分布。真实语义匹配优先于数量平衡。难判定的句子应结合上下文复核，仍有歧义就标记供人工确认，**不要默认归灯或随意凑数**。
4. 尊重文本：保留诗歌原有行分隔（JSON 用 `\n`）、必要的段落空行（`\n\n`）、中文引号与正确标点；清理 EPUB/OCR 残留、注释序号、下载站信息，不任意删改句意。译文版本差异不能凭印象混合。
5. 来源可靠：作者、篇名、章节、角色、译者（如果需要注明）要有来源依据。**独立作品被收录在合集/文库中时，优先使用其独立篇名，而不是合集销售标题**；无法查证时保留可证信息、作者可留空，不得臆填。
6. 保持网站**纯文本、无第三方后端和轻量化**；不要为录入电影/歌曲上传大尺寸剧照、音视频文件或整部作品。注意著作权：引用保持必要的短摘录，尤其不要公开上传大段受保护的歌词或剧本。
7. **日签创作者禁收名单（站长指定）：樱雪丸**，包括「櫻雪丸」「桜雪丸」等常见字形变体。无论涉及何种作品或媒介，都不得新录入该作者的内容，也不得以作者字段留空或改变署名规避限制。既有误收的《高清日本史5 战国时代：逐鹿关原》条目已从总池移除。`tools/validate_daily_sign.py` 负责在网站构建前拒绝禁收作者和已知误收作品；新增候选须在入池前核对来源作者。本禁收名单仅适用于本站日签系统，不影响其他栏目。

## 二、十四准则与判定边界

下面的英文键必须与 `assets/js/sign-aspects.js` 中的名称完全一致。这里的示例描述是**分类判据**，不是检测关键词的充分条件。

| aspect | 中文 | 主要语义 | 容易混淆时怎么区分 |
| --- | --- | --- | --- |
| `lantern` | **灯** | 理性、认知、求真、启迪、洞察；知识本身可能冷酷、不仁，求知可能令人疯狂 | 单有“科学/光/思想”不够；若核心是建设→铸、探索远方→引、维持生命→心，则选后者 |
| `forge` | **铸** | 工程、技术、生产、创造、锻造、摧毁旧物与建造新世界 | 革命的**斗争过程**→刃；革命后的**建设和改造**→铸 |
| `edge` | **刃** | 对抗、革命、战争、冲突、权力争夺、意志与决断 | 苦难中的坚持与彼此守护→心；仅有暴力意象但更重死亡和余烬→冬 |
| `winter` | **冬** | 死亡、终结、静默、失落、怀念、哀悼、无可挽回的消逝 | 涉及历史但重“逝者/遗忘的哀伤”→冬；重历史叙事和时代回声→秘史 |
| `heart` | **心** | 生命持续、守护、关怀、韧性、治愈、团结与陪伴 | 强烈的感官渴望、爱欲、占有或欢愉→杯；草木生态的蓬勃生长→蜜 |
| `grail` | **杯** | 爱欲、渴求、肉体、享乐、饥渴、欢欣与伴随的痛楚 | 宽厚而持续的友谊/守护→心；迷乱本能和不可知的蜕变→蛾 |
| `moth` | **蛾** | 无意识、本能、混沌、幻觉、迷狂、伪装、蜕变与荒诞 | 以证据追求危险真理→灯；受本能和错觉驱使的疯狂→蛾 |
| `knock` | **启** | 钥匙、门户、边界、解锁、通行、打破限制、跨越不可能 | 注重**越过门槛的瞬间**→启；注重门外的**漫长旅途与新地平线**→引 |
| `histories` | **秘史** | 历史、编年、叙事的裂隙、文明兴衰、史迹与记忆的留存 | “过去”只是陪衬时不必归秘史；哀悼亡者→冬，远古血脉/地层→鳞 |
| `rose` | **引** | 远方、道路、航行、追寻、理想、地平线、星际探索和希望 | 宇宙的**航行/抵达/求索**→引；宇宙的**规律、协调与星象之美**→穹 |
| `nectar` | **蜜** | 草木、自然生态、田野、季节、野性生机、生命的有机生长 | 重点是人的生命与关系→心；大地深处的古老与原始血脉→鳞 |
| `sky` | **穹** | 天空、音乐、旋律、数学规律、和谐、秩序、天体运行 | 重点是理解真理的理性过程→灯；飞向群星的事业→引；自然草木景观→蜜 |
| `scale` | **鳞** | 岩层、大地深处、史前生命、祖先血脉、古老沉睡之力 | 时间长不等于鳞；叙述政治/文明历史→秘史；现代采矿机械→铸 |
| `moon` | **月** | 夜幕、隐秘、禁忌、海洋、潮汐、秘密与朦胧 | **海上远航**→引；仅为背景的月亮不自动归月；怀念失去的人→冬 |

**判断顺序：**

1. 先问“这段话真正要表达什么”，再看修辞和意象，而不是先看名词。
2. 挑出至多两个有说服力的候选准则，比较各自与句子核心的吻合度。
3. 若灯与非灯同样吻合，非灯优先；若主题确为真理/理性的冷酷或追求，则灯优先。
4. 保存**一个**经复核的显式 `aspect`。没有充足依据时记录待确认，不要用关键词分类器的输出直接发布。

`assets/js/sign-aspects.js` 有启发式回退方法 `classify()`，只用于旧数据缺字段时的容错显示。**新增日签必须由录入者明确填入 `aspect`。** `get()` 会优先尊重显式标签。

## 三、数据格式（保持与现有网页兼容）

**唯一正式总池：** `assets/data/quote-pool.json`，结构为 `{"version":3,"count":条数,"quotes":[...]}`。新增条目直接**追加至 `quotes` 末尾**，更新 `count`；绝不重建、洗牌、按准则排序全池。默认日签分配依赖池的既有次序和权重，洗牌会改变将来的确定性抽取结果。

现有网站使用的字段：

| 字段 | 要求 | 维护说明 |
| --- | --- | --- |
| `id` | 必需、全池唯一的稳定字符串，推荐 64 位十六进制 | 新增时生成一次；后续改错别字、准则、来源、权重时**不再重新生成**，否则已抽记录及点赞可能脱钩 |
| `text` | 必需、非空 | 保留原句、译本、引号、诗行（`\n`）；不要把作品名、注释、下载文件名写入这里 |
| `book` | 必需、非空 | 这是**所有媒介的统一“作品标题”字段**：小说/短篇篇名、电影名、歌曲名、演讲题名；不要改名为 `movie` 或 `song` 而破坏现有页面 |
| `author` | 必需字符串，未知可为 `""` | 小说/诗歌为作者；电影台词优先可确认的编剧/原文作者（无法确认则留空，角色放 `chapter`）；歌曲优先作词人，演唱者可备注在 `chapter` |
| `chapter` | 必需字符串，可为空 | 小说卷章/短篇篇名、电影角色及场景、歌曲主歌/副歌及演唱信息、演讲时间场合等 |
| `readerLink` | 必需字符串，可为 `""` | **目前只渲染 `https://weread.qq.com/` 的微信读书链接**。电影/歌曲无匹配来源时留空，不要伪造链接；新增其他平台跳转必须另行修改链接渲染与校验 |
| `weight` | 必需、正数 | 作品层级的抽取权重。历史值常用 `1`、`1.35`、`1.6`、`1.85`；新作品默认 `1`，**不要因同一本书摘录多而无限提高权重** |
| `quoteWeight` | 必需、正数 | 作品内部该句抽取权重，新句默认 `1`；特别偏爱且有充分理由时可为 `1.25` |
| `theme` | 必需；`reflection` / `inspiration` / `scenery` | 旧格式辅助标签；分别为哲思、鼓舞、景物。**不等于准则，不代替 `aspect`** |
| `aspect` | **必需；14 个合法英文键之一** | 对每句独立确定的主要准则，严禁缺省后交给浏览器猜测 |
| `sourceType` | **可选** | 给新增跨媒介素材添加 `fiction`、`poetry`、`nonfiction`、`film`、`song`、`speech`、`other`；旧 1060 条未设置无需补写，页面仍正常工作 |

三种**格式示意**（仅演示字段，**不是待发布的真实引文**；其中 `id` 必须换成正式生成的唯一值）：

```json
{
  "id": "请生成一次性的唯一id",
  "text": "【这里填写有出处的小说摘句】",
  "book": "小说正式书名",
  "author": "小说作者",
  "chapter": "第三章",
  "readerLink": "",
  "weight": 1,
  "quoteWeight": 1,
  "theme": "reflection",
  "aspect": "lantern",
  "sourceType": "fiction"
}
```

```json
{
  "id": "请生成一次性的唯一id",
  "text": "【这里填写必要而简短的电影台词】",
  "book": "电影正式片名",
  "author": "",
  "chapter": "角色名｜场景（已核实）",
  "readerLink": "",
  "weight": 1,
  "quoteWeight": 1,
  "theme": "inspiration",
  "aspect": "heart",
  "sourceType": "film"
}
```

```json
{
  "id": "请生成一次性的唯一id",
  "text": "【这里填写必要而简短的歌词摘句】",
  "book": "歌曲正式曲名",
  "author": "作词人",
  "chapter": "演唱者｜副歌",
  "readerLink": "",
  "weight": 1,
  "quoteWeight": 1,
  "theme": "scenery",
  "aspect": "sky",
  "sourceType": "song"
}
```

注意示例中 `aspect` 仅为格式占位，实际新签仍须逐句分类，**绝不能因为是电影就自动归心，或因为是歌词就自动归穹**。生成 ID 可用：

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

## 四、不同媒介的录入细则

- **书籍划线、诗歌、散文：** 优先使用独立作品的官方名称；短篇若在合集里，请填写短篇篇名；`chapter` 可记录章节、篇内位置或卷册。诗句按原排版分行，确认中文译文标点。
- **电影台词：** `book` 填片名，`chapter` 记录**角色及场景**，电影年份/版本存在歧义时保留到章节或新增备注字段，而非污染作品标题。角色名不是编剧，也不能无依据把名言归给演员。
- **歌词：** `book` 填曲名，`author` 优先写作词人（核实词曲与翻唱关系），`chapter` 可存“演唱者｜主歌/副歌”；注意单曲、专辑、翻唱和现场版不是一回事。**以有独立意义的完整歌词句／完整意群为优先，不人为截成两三个词或无谓语的半句话**；同时只使用必要且可合法公开的短摘录，禁止收录完整或大量受版权保护的歌词。歌词文本不足以合法完整引用时，保留可确认的原文并标记待人工补核，不能杜撰缺失部分。
- **演讲、访谈、杂志：** 记录实际发言者和具体篇名；`chapter` 可写日期、会议、期号或访谈段落。引文不能来自二手转述而被误标为逐字原话。
- **英文与翻译：** 尊重选择的译本。若提供双语版本，应事先决定 `text` 采用哪种正文展示方式；不要自动拼接成带乱码或冗余书名的超长签文。

## 五、后续新增日签的标准流程

1. 收集候选句子，保留原始来源、作品信息、章/角色/歌词段落和必要的核对线索；确认每段摘录可合法公开使用。
2. 校对文字、标点、行分隔、作品标题以及作者。去掉 EPUB/Z-Library 下载标记、版本噪声、无根据的作者归属和网页乱码。
3. 逐句依据**第二节的十四准则**确定一个 `aspect`；同时给 `theme`，可选填 `sourceType`。有歧义请复核，不默认为灯；确定属于理性启迪的也不要避开灯。
4. 为每条新签分配独立、持久的 `id`，填齐兼容字段；使用合理权重，**只追加新条目**，将 `count` 更新为 `quotes.length`。禁止修改旧 `id`、旧签文的已确认准则及已有的私人评分存储键。
5. 运行 `python3 tools/validate_daily_sign.py`；发现不符合规范的输入应停止发布并修复。不通过时**不要让运行时启发式标签替代缺失的显式准则**。
6. 通过 GitHub Pages 构建与实际页面检查：首页日签、重抽、14 准则标记、折叠签册、新旧日期倒序、点赞点踩、来源链接及手机布局均保持正常。
7. **北京时间零点换签不变。** `tools/update_daily_sign.py` 与 `assets/js/sign-calendar.js` 使用同一日期和加权挑选逻辑；`_data/daily_sign.json` 是当日签，`_data/daily_sign_history.json` 是已公布历史，**不因扩池而改写过去**。扩池后未来日期可能抽到新签，这是预期行为。

## 六、长期不得破坏的旧功能

- `assets/js/sign-aspects.js` 维护准则图标、色彩及显示；文字正文本身**不染准则色**，尽量复用原有雪碧图，不加大图。
- 默认日签在北京时间 `Asia/Shanghai` **每日 00:00** 更新，GitHub Actions 每日 `16:00 UTC` 负责仓库归档，网页端自检日期作为延时兜底；不应为了新增签文更改定时。
- 重抽过的个人签册按**日期、新旧重抽的真实时间倒序**排列；《奇怪的小玩意》中的签册**默认折叠**，从首页 `#rc-archive-title` 直达时才展开。
- `♡ 贴贴` 与 `🐾 踩踩` 的评价仅存浏览器的个人 `localStorage`，可手动导出/导入；新增签文不得私自上传用户评价到 GitHub、服务端或第三方。
- 保留旧签 ID、记录、内容、抽签权重及默认日签历史。不要因重分类、改排版或导入新素材清理用户已有的个人数据。
- 所有新增规范继续遵循仓库根目录 `AGENTS.md` 的轻量化、内容和发布约束。

## 七、Simon & Garfunkel 等双语歌词签的显示约定（2026-10-14）

- 每条歌词签使用 `sourceType: "song"`，`book` 保持正式歌名，`author` 填经核对的作词者；翻唱曲要区分原作者与 Simon & Garfunkel 的演唱身份。
- `text` 以双语形式呈现：**优先采用可以独立表达完整意思的真实英文歌词短句（或完整意群）**、换行、对应本站自译中文；如需解释，可在后面保留明确标注的 `〔歌意〕`，但解释**不能冒充英文歌词，也不能代替原句校对**。不要为了追求「极短」强行截断句子；允许为准确表达保留合理长度、必要的原文诗行换行。名曲可保留两三个不同摘录，每一条分别配准则；单首歌的整体引用仍须克制且符合版权限制。
- `chapter` 仍用 `演唱：歌手｜专辑：英文原名（发行：YYYY）｜首发：YYYY` 记录可核实的来源信息；完整日期可保留已有数据，若只能核实年份则只填年份，不得臆造月日。首次公开发行早于专辑（先发单曲）时，以该演唱版本的**首次发行年份**为准。旧签的完整来源数据不删除。
- 新增歌词的站内显示统一精简为**歌名 · 演唱者／乐队 · 发行年份**。作词者、专辑和完整日期只保留在数据源用于溯源，**不再出现在首页／重抽／签册的来源栏**；英文摘句和对应中文自译仍显示在正文。
- 首页默认日签、手动重抽、签册（含无 JavaScript 时的降级文本）均通过 `chapter` 的 `演唱：` 前缀识别歌曲，显示**歌名、演唱者／乐队、发行年份**三项；旧签、历史记录与非音乐签保留原格式。仅用纯文字，不附加封面、音频或图片。
- 新增歌词签仍只追加于 `assets/data/quote-pool.json` 末尾，并运行原有 `tools/validate_daily_sign.py` 验证。已有 ID、排序、历史与本地投票不可修改。


### 歌词不完整条目的修订与人工校核（2026-10-15）

- 站长明确要求：**保留全部既有歌词签**，不得通过删除、隐藏、降低抽取权重或自动筛掉碎片来“解决”摘录不完整；后续应在**同一条签文、同一稳定 `id`** 上修订英文与对应中文自译。
- 修订优先级：核实真实录音版本与歌词来源 → 判断当前片段是否构成独立句子／完整意群 → 在**有合法依据的原始歌词文本可供使用**时补齐，而非靠模型续写、把多个不相邻片段拼成伪歌词，或将歌意解释冒充原词。修改英文后同步核对中文语义及十四准则。
- **语义完整并不等于字符越多越好。** 「I miss you.」一类简短而完整的表达可以保留，单独的虚词、句子开头、脱离上下文的名词短语则优先复核；不能用统一最短字符数当作硬性删除条件。
- 版权仍然有效：**不得把未经许可取得的受保护歌词由 AI 按片段续写成逐字完整句子**。若缺少可使用的原文或引用权限，保持原始条目，并通过编辑审查记录说明待补的原因；可以附加明确标记的原创意译/歌意说明作为补充，但不得声称它是原词。
- 修订既有歌词时，`book`、`author`、`chapter`、`sourceType`、旧记录和评分关联保持兼容，尤其**禁止改变 `id`**；不重新排序、不重建总池、不写回签册与每日历史，不变更北京时间零点更新和「搅拌均匀」设置。
- 批量修订前运行 `python3 tools/audit_song_excerpts.py` 查看**待人工复核候选**。该脚本只读取数据、不自动补词、不隐藏短签、不影响网站构建；它提示过短摘录，但短不必然不完整。

## 八、重抽「搅拌均匀」设置（2026-10-14）

- 首页二级操作区有 `🥄 搅拌均匀：开／关` 按钮。默认开启，状态用 `aria-pressed` 表示，仅存当前浏览器 `localStorage['rc-sign-mix-v1']`；跨标签页 `storage` 同步，禁用存储时本页照常使用。不得将个人偏好上传。
- **只影响手动重抽**：北京时间每日零点确定性日签、`assets/js/sign-calendar.js` 与 `tools/update_daily_sign.py`、官方归档不变。「回到今日日签」仍恢复原签。
- 分为三个媒介类别：`sourceType: song` → 歌词，`sourceType: film` → 电影台词，其他类型（含历史无 `sourceType` 的文摘）→ 文摘。先执行旧有「已抽签不重复」及尽量避开最近作者，再优先排除**当前显示签文**的媒介类型，从其余可选类别等概率选一个，最后按**原有作品权重及句子权重**抽取。其他类别耗尽时允许退让，不得提前终止抽签。关闭则原样使用此前的按作品权重抽签算法。
